4. Acesse as URLs:
   - NuP-Study:    https://seu-dominio.replit.dev/

🎯 O QUE FOI IMPLEMENTADO:
=============================================================================

✅ Proxy Reverso no NuP-Study (porta 5000)
   - Intercepta /nup-identify → encaminha para localhost:5002
   - Intercepta /nup-aim → encaminha para localhost:34735
   - Suporte a WebSocket para Hot Module Replacement (HMR)
   - Logs detalhados de todas as requisições proxy

✅ NuP-Identify configurado para servir em /nup-identify
   - BASE_PREFIX configurado via variável de ambiente
   - Assets Vite ajustados para o prefixo
   - HMR path: /nup-identify/__vite_hmr

✅ NuP-AIM configurado para servir em /nup-aim
   - BASE_PREFIX configurado via variável de ambiente
   - Assets Vite ajustados para o prefixo
   - HMR path: /nup-aim/__vite_hmr

✅ Scripts de Startup Criados
   - start-nup-identify-proxy.sh
   - start-nup-aim-proxy.sh
   - Configuram BASE_PREFIX automaticamente

🔍 VERIFICAÇÃO:
=============================================================================

Terminal 1 - Testar Proxy:
   curl -I http://localhost:5000/nup-identify
   # Deve retornar: HTTP/1.1 200 OK

Terminal 2 - Ver Logs do Proxy:
   # Nos logs do "Start application", procure por:
   # [Proxy] NuP-Identify: GET /nup-identify

=============================================================================
🐛 TROUBLESHOOTING:
=============================================================================

PROBLEMA: Scripts não têm permissão
SOLUÇÃO:
   chmod +x start-nup-identify-proxy.sh start-nup-aim-proxy.sh
   kill 1

PROBLEMA: Portas em conflito
SOLUÇÃO:
   pkill -f "PORT=5002"
   pkill -f "PORT=5003"
   kill 1

PROBLEMA: BASE_PREFIX não aplicado
SOLUÇÃO:
   Verifique os logs dos workflows NuP-Identify e NuP-AIM
   Deve aparecer: "🔧 [Proxy Mode] Starting... with BASE_PREFIX=/nup-..."
